# Project Structure and Ownership

The application runs as one Streamlit service. Launch it locally with `python -m streamlit run app.py`; hosted services use `python start.py`.

| Location | Responsibility |
| --- | --- |
| `app.py` | Entry point, workspace layout, and playback updates |
| `start.py` | Hosted process startup and port validation |
| `uav_logistics/core/data.py` | Network profiles, fleet data, and request presets |
| `uav_logistics/core/mission_engine.py` | Triage, constraints, scoring, routes, verification, and aircraft lifecycle |
| `uav_logistics/ui/state.py` | Session initialization, key selection, and event records |
| `uav_logistics/ui/components/` | Mission Control, Fleet & Network, Intelligence, Reports, and map views |
| `uav_logistics/ui/styles.py` | Shared presentation styles |
| `uav_logistics/ui/themes.py` | Theme tokens and map style URLs |
| `static/` | Bundled map styles, served beside the root Streamlit entry point |
| `tests/` | Mission behavior, Streamlit interactions, themes, and deployment validation |
| `docs/` | Detailed simulation and hosting instructions |

## Working conventions

Keep planning and flight lifecycle changes in `core/`; keep interface and session presentation changes in `ui/`. Imports use the `uav_logistics` package. The existing engine still contains some Streamlit/PyDeck helpers and the data module uses theme colors; this cleanup groups responsibilities without redesigning the engine.

`core/data.py` resolves the repository root so optional `.env` configuration loads consistently after the move. Static URLs remain `/app/static/daylight_basemap.json` and `/app/static/night_basemap.json`. Both local and hosted launchers run the same root `app.py`.

Keep credentials in the ignored `.env` or hosting environment. Generated bytecode, virtual environments, caches, logs, and build artifacts are ignored. The older standalone API and local archived screenshots are not needed to run this repository.

## Validation and limits

GitHub Actions installs the development requirements and runs the suite on Python 3.12 / Linux. Tests cover dispatch, safety constraints, aircraft lifecycle, session isolation, theme switching, static styles, environment loading, and hosted startup.

This remains a simulator with session-local history, optional Gemini triage, and no application login or durable database. See [the simulation guide](SIMULATION_GUIDE.md) for behavior and [the Render guide](RENDER_DEPLOYMENT.md) for hosting.
